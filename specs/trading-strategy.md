# VibeSpec：trading-strategy

## 1. Spec

### 目标

- 记录一份可在插件内展示的“持仓管理 + 选股逻辑”策略描述，作为后续监控和筛选的统一规则来源。
- 新增持仓股功能：用户可维护 A 股持仓信息，插件基于持仓策略对持仓股进行监控并给出风险提示。
- 新增推荐 A 股列表：每天北京时间 10:00、15:00，在插件已能获取行情的 A 股集合中按选股策略生成推荐列表，并在策略页面展示。
- 推荐列表只表达“命中当前可计算策略条件”，不表达自动交易建议，不下单，不自动买卖。

### 修改范围

- 新增策略规则、持仓监控、推荐选股的本地 TypeScript 服务。
- 新增策略中心 Webview，用于展示策略描述、持仓配置、监控结果和推荐 A 股列表。
- 复用现有 `leek-fund.stockWindVane` 命令入口打开策略中心，不修改 `package.json` 命令声明。
- 在插件激活后启动本地定时任务，按北京时间 10:00、15:00 生成推荐列表。
- 使用现有股票行情与 K 线获取能力，不新增依赖，不接入新的全市场数据源。
- 允许修正当前未跟踪的 `src/shared/technicalAnalysis.ts` 中影响编译和策略计算的明显语法问题。

### 非目标范围

- 不做全市场 A 股扫描；本次推荐范围仅限插件当前能获取行情的 A 股集合，包括自选股和保存后的持仓股。
- 不接入账户、券商、交易、下单、撤单、资金划转能力。
- 不自动买入、卖出或修改用户持仓。
- 不新增数据库、服务端、外部任务调度、环境变量或生产配置。
- 不新增依赖，不修改 lock 文件，不做无关目录迁移。
- 不修改现有价格预警、状态栏、股票树排序、添加删除股票等已有行为。
- 对当前数据无法验证的策略项，例如龙头地位、政策催化、行业 PE、负面公告，必须标记为“需人工核验”，不得伪造通过。

### 验收标准

1. 策略中心能展示完整策略描述，包括持仓纪律、选股漏斗和买入前检查项。
2. 用户能在策略中心保存持仓股信息，至少包含股票代码、成本价、持仓数量、买入日期，可选止损价、目标价。
3. 保存持仓后，持仓股票会进入插件行情池，后续刷新可用于持仓监控。
4. 持仓监控能基于当前行情检查单票仓位上限、硬止损、时间止损、账户单日熔断，并显示风险等级和原因。
5. 每天北京时间 10:00、15:00，插件运行时会自动生成推荐 A 股列表。
6. 用户可在策略中心手动触发一次推荐列表刷新。
7. 推荐 A 股列表基于当前可计算条件筛选：大盘在 20 日均线之上、个股均线多头、股价位于关键均线上方、右侧启动信号、股性活跃、盈亏比不低于 3:1。
8. 推荐项必须展示推荐原因、止损价、目标价、盈亏比，以及仍需人工核验的策略项。
9. 定时任务不会创建外部自动化，不会在插件未运行时后台执行。
10. 未修改非目标范围内功能，未新增未说明依赖，自动化验证至少通过 TypeScript 编译或明确记录失败原因。

## 2. Task Card

### 当前任务

实现本地策略中心、持仓监控与定时推荐 A 股列表。

### 允许修改

- `specs/trading-strategy.md`
- `src/shared/tradingStrategy.ts`
- `src/shared/strategyScheduler.ts`
- `src/shared/technicalAnalysis.ts`
- `src/webview/strategyCenter.ts`

- `src/extension.ts`
- `template/strategy-center.html`
- `template/scripts/strategy-center.js`
- `template/styles/strategy-center.css`

### 禁止修改

- 禁止修改 `package.json`、任何 lock 文件及构建配置。
- 禁止新增依赖。
- 禁止接入新的外部全市场数据源。
- 禁止修改现有股票树、状态栏、价格预警的既有业务语义。
- 禁止自动 commit、push、merge。
- 禁止将任何密钥、Token、生产地址或敏感配置写入仓库。

### 执行步骤

1. 读取本 Spec，确认目标、边界和允许修改文件。
2. 新增策略规则服务：定义策略描述、持仓配置类型、持仓监控、推荐筛选与推荐缓存。
3. 修复并复用技术分析 K 线能力，保证推荐筛选可获取均线、MACD 等指标。
4. 新增策略中心 Webview，支持策略展示、持仓编辑、监控结果和推荐列表展示。
5. 注册 `leek-fund.stockWindVane` 命令打开策略中心。
6. 在扩展激活时启动北京时间 10:00、15:00 的本地定时推荐任务，并在停用时释放定时器。
7. 执行 TypeScript 编译验证；如失败，区分本次修改问题与既有未提交变更问题。
8. 基于 Spec、Task Card 和 git diff 填写 Review Report，输出 Diff Summary。

### Review 检查点

- 是否满足策略描述、持仓监控、推荐列表三类目标？
- 是否严格限定推荐范围为当前行情池，而非伪造全市场扫描？
- 无法计算的策略项是否明确标为人工核验？
- 是否新增依赖或修改 package/lock 文件？
- 持仓监控是否可能误触发自动交易行为？
- 定时任务是否正确释放，避免插件停用后残留。
- 是否存在无关重构、大面积格式化或修改非目标功能？
- 编译和关键路径验证是否完成并记录？
