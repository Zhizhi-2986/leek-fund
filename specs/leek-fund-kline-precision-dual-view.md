## 1. 目标与原则

### 1.1 本次要解决的核心问题

当前 5 分钟 K 线存在明显的“价格与图形对应不上”的使用感受，尤其是：**顶部行情已经显示当日最低价，但在 K 线可见区域中找不到对应的最低价影线或标注**。

截图观察：当前选中股票为国际复材（`sz301526`），界面顶部显示当日最高 `20.27`、最低 `18.52`，而图表右轴在截图可见区域标示约 `20.35 / 19.87 / 19.40`。截图底部被 DSH 任务浮层部分遮挡，**不能据此断定 K 线数据一定缺失**；必须先辨别数据、坐标和可视区域三类原因。

本次改动目标：

1. **数据真实**：各根 5 分钟蜡烛的 `open/high/low/close` 与原始行情数据严格一致；不得捏造最高/最低影线。
2. **坐标准确**：蜡烛、影线、均线、刻度、价格辅助线共用同一 Y 轴映射。
3. **极值可见**：K 线数据中真实存在的最低价和最高价，必须位于完整可见绘图区内，且能被明确识别。
4. **差异可解释**：若当日行情快照最高/最低与 5 分钟 K 线聚合极值不一致，清晰提示，不静默伪装成一致。
5. **视觉清晰**：解决图表过高导致底部被遮挡、Retina 绘制不清晰、蜡烛与影线不对齐等问题。
6. **交互适度**：保留现有行情 Tab，增加“当日数据 / 5 分钟 K 线”手动切换；**不开发分时图**。

### 1.2 范围控制

- **允许改动**：现有 5 分钟 K 线数据处理、渲染算法、图表容器布局、少量行情字段适配、当前股票详情视图。
- **不应改动**：自选树管理逻辑、一级/二级分组、模型工具对外接口、提醒规则体系、第三方行情源的整体架构。
- **不做重构**：不因本需求新建大型 QuoteService / StateService，不引入数据库，不替换完整图表技术栈，除非现有代码确实无法满足测试。
- **不改交易语义**：不新增自动买卖、策略选股、港美股或资金流向分析。
- **保留约束**：DSH 侧边栏与工作区 Tab 都可使用，延续 React 18 + 当前项目构建流程。

## 2. 必须先做的根因排查（先排查，再修复）

### 2.1 建立可追踪的单次行情样本

对同一只证券、同一交易日，记录并对照以下原始资料：

| 数据项 | 从哪里获取 | 用来判断什么 |
|---|---|---|
| 行情快照 `dayHigh/dayLow` | 现有实时报价接口（示例：新浪） | 页面头部最高/最低价的来源 |
| 原始 5 分钟 K 线数组 | 现有腾讯 K 线接口 | 数据源是否真的覆盖日内极值 |
| 标准化后的 K 线数组 | 进入图表组件前 | 解析、排序、过滤时是否遗漏极值 |
| `min(bar.low)` / `max(bar.high)` | 标准化后的数组 | K 线自身的当日极值 |
| 当前绘图区边界 `plotTop/plotBottom` | 图表布局计算 | 最低影线是否被裁切 |
| 价格范围 `domainMin/domainMax` | 坐标算法 | Y 轴范围是否正确包含极值 |
| `priceToY(minLow)` | 坐标算法 | 最低价应该对应的像素位置 |
| 源数据交易日/时间 | 两个数据源 | 是否混用不同交易日或不同时间段 |

建议仅在开发环境通过开关输出调试结果，例如：

```ts
{
  symbol: 'sz301526',
  quoteDayLow: 18.52,
  quoteDayHigh: 20.27,
  barCount: 42,               // 仅为示例，实际以抓取结果为准
  barMinLow: null,            // 从真实 K 线计算后填入
  barMaxHigh: null,
  domainMin: null,
  domainMax: null,
  plotTop: null,
  plotBottom: null,
  yOfBarMin: null
}
```

**禁止将示例 `18.52`、`20.27` 或 `barCount` 写成生产逻辑中的固定值。**

### 2.2 根因判断矩阵

| 实际发现 | 根因类别 | 修复方向 |
|---|---|---|
| 原始 K 线已包含 `18.52`，标准化后丢失 | 数据解析/过滤错误 | 修正解析、分桶、排序及完整性校验 |
| 标准化后包含 `18.52`，但 `priceToY(18.52)` 在绘图区外 | Y 轴 domain 错误 | 统一价格范围计算及绘图区边界 |
| 影线坐标正确，但位于页面可见区域下方 | 容器尺寸/滚动错误 | 限制图表适配容器，禁止底部内容被截断 |
| 标准化后最低值高于快照最低价 | 数据源覆盖/口径差异 | 显示来源差异提示；核实集合竞价、起止时点、缺失 K 线 |
| 价格轴刻度与蜡烛同价位不一致 | 多套映射/双轴换算错误 | 刻度和图元复用同一套 `priceToY` |
| 最新柱走势与现价不一致 | 未完成 K 线/刷新时点差异 | 标识当前柱状态及不同数据更新时间 |

> **P0 规则**：没有确认根因之前，不允许仅扩大坐标轴下限来“补出”某个最低价；更不允许把快照最低价强行写进任意一根 K 线的 `low`。

### 2.3 根因诊断结论（2026-11-02，真实线上样本，sz301526 国际复材）

取同日实际接口响应对照（诊断脚本结果，非截图示例值）：

| 数据项 | 数值 | 来源 |
|---|---|---|
| 行情快照 最高/最低 | `20.27 / 18.52` | 新浪实时报价 `hq.sinajs.cn/list=sz301526`（2026-11-02 15:31:00） |
| 腾讯 5 分钟原始数组 | 160 根（10-28 后段 16 + 10-29 48 + 10-30 48 + 11-02 48） | `ifzq.gtimg.cn/appstock/app/kline/mkline?param=sz301526,m5,,160` |
| 标准化数组 OHLC 不变式 | 全部通过（`low ≤ min(o,c)`、`max(o,c) ≤ high`，48/48） | 脚本校验 |
| **当日 K 线 `min(low)` / `max(high)`** | **`18.54`（09:35 柱） / `20.26`（09:50 柱）** | 脚本计算 |
| 快照与 K 线极值差 | 最低差 `0.02`（2 tick）、最高差 `0.01`（1 tick），均为 1-2 个最小报价单位 | 对账 |

**结论：根因类别 = “数据源覆盖/口径差异 + 缺少可视化解释”**，不是解析丢失、也不是坐标错误：

1. 腾讯 5 分钟 K 线解析、过滤、排序均正确，`18.52 / 20.27` 从未出现在 5 分钟源中；解析层没有丢数（原始数组与标准化数组极值一致）。
2. 当前绘图代码（`buildYRange` 含昨收 + 5% 留白）本身保证 bar 极值在画布内，坐标无越界；真正的问题在 UI 层：**没有任何极值标注、没有 hover 核对、没有“快照极值与 K 线极值不一致”的提示**，用户天然以为“顶部显示 18.52，图里就应该找得到 18.52”。
3. 口径差异原因：新浪快照最高/最低覆盖含集合竞价在内的全天定价（09:15 起撮合），而 5 分钟 K 线的首根桶为 09:30–09:35 聚合；开盘竞价极值（本日为 18.52，低于 5 分钟桶最低影线 18.54）不进入任何 5 分钟桶，属于数据源覆盖差异，**不是坐标轴裁切**。
4. 附带发现：`detail.ts` 中 `fetchTencentM5` 默认 `count=60`，仅够当日柱 + 十余根历史柱，**无法为图表提供完整 MA60 的 5 分钟收盘序列上下文**（第 3.4 节）；MA 目前按日 K 收盘计算，与第 3.4 节“5 分钟 SMA”语义不符，需一并修正。

据此修复方向：保留 K 线源真实极值（18.54/20.26）与真实蜡烛图形；增加极值标注、hover OHLC、对账提示（“行情最低 18.52；当前 5 分钟数据未覆盖该价格”）；补 5 分钟历史序列计算 MA5–MA60；按原型实现双视图与自适应布局。

## 3. 5 分钟 K 线数据正确性

### 3.1 最小数据契约

在现有数据层内规范进入渲染器的数据（类型名仅为建议，不要求与已有类型重复）：

```ts
interface CandleBar5m {
  timestamp: number;     // 统一的时间戳；渲染前按升序排列
  open: number;
  high: number;
  low: number;
  close: number;
  volume?: number;
  completed: boolean;    // 最后一根是否已经收盘
}
```

逐根校验：

- 时间戳合法、同交易日、顺序递增，无重复时段。
- 四个价格均为有限正数。
- `low <= Math.min(open, close) <= Math.max(open, close) <= high`。
- 不使用字符串格式化后的两位/三位小数继续参与几何运算；保留原始价格数值，**仅展示阶段按证券实际报价精度格式化**。
- 异常数据不得默默改造成合法数据；记录可诊断原因，按既有 UI 模式提示不可用或局部缺失。

### 3.2 时间桶与缺口

- A 股完整连续竞价时段通常形成 **48 根 5 分钟柱**；盘中只应展示截至当前已取得的时段。
- 供应商的时间戳可能表示桶起点或终点，**必须通过接口样本确认其具体语义**；不能无条件给时间加减 5 分钟。
- 特别核对 `09:30–09:35`、`11:25–11:30`、`13:00–13:05`、`14:55–15:00` 四个区间。
- 不把午间休市当成连续交易 K 线；时段缺失不以假的 OHLC 补齐。
- 处理休市日、半交易日等特殊情况时应依照适用交易日历，不直接假设所有交易日均完全一致。
- 如接口返回的 5 分钟数据不覆盖开盘集合竞价或其他交易阶段，应明示该差异，不能将其与快照全日最高/最低强行视为一致。

### 3.3 日内高低价对账

计算：

```ts
const barsHigh = Math.max(...validBars.map(b => b.high));
const barsLow = Math.min(...validBars.map(b => b.low));
```

同一交易日且数据口径可比时，对照行情快照：

- `barsHigh` 与 `quote.dayHigh`
- `barsLow` 与 `quote.dayLow`

比较容差需按证券实际最小价格变动单位（tick size）确定，避免用固定 `0.01` 误判 ETF 等不同报价精度的证券。**容差只能用于识别差异，不得用于修改原始 K 线。**

若确认为差异：

1. 保留原始 K 线的真实极值和真实蜡烛图形。
2. 在图表标题/说明区域显示简洁提示，例如：`行情最低 18.52；当前 5 分钟数据未覆盖该价格`。
3. 可以展示最近一次更新时点和数据来源以协助判断。
4. 不把缺失价位直接画成一根影线，不伪造“最低价已出现”的视觉效果。

### 3.4 MA5 / MA10 / MA20 / MA30 / MA60

- MA 为 **5 分钟收盘价序列**的简单移动平均（SMA），不是日 K 均线。
- 只展示当日蜡烛，但可使用此前交易日足够长的 5 分钟历史序列作为 MA 的计算上下文。
- 完整一个交易日通常只有 48 根 5 分钟 K 线，因此仅靠当日数据不能完整计算 MA60。
- 若历史序列不足，缺失的 MA 数值显示 `—` 或不绘制对应线段，**不能用不足窗口的平均值冒充 MA60**。
- MA 指标线的坐标映射必须与蜡烛价格轴一致。

## 4. Y 轴与蜡烛绘制精度（最核心实现）

### 4.1 唯一价格范围计算

对当前实际展示的所有有效 K 线，先取：

```ts
const rawMin = Math.min(...bars.map(b => b.low));
const rawMax = Math.max(...bars.map(b => b.high));
```

边界应覆盖图中实际要绘制的数值：

- 蜡烛的 `high`、`low` 是强制包含项。
- 需要完整绘出的 MA 线或参考价格线如超出蜡烛区间，应明确纳入计算或采用可解释的超范围样式，不允许在没有说明的情况下被错误裁切。
- 不能仅使用 `open/close` 或“涨跌幅绝对值”决定 Y 轴边界。
- 不采用固定的涨跌幅区间替代真实价格区间。

适当增加上下像素留白，例如价格范围的约 3%～6%，并保证极值标注有显示空间。对于 `rawMin === rawMax` 的无波动情况，采用基于报价最小变动单位的非零安全范围，避免除以零。

### 4.2 统一 Y 坐标函数

```ts
interface PriceScale {
  min: number;
  max: number;
  top: number;
  bottom: number;
}

function priceToY(price: number, scale: PriceScale): number {
  const height = scale.bottom - scale.top;
  return scale.top +
    ((scale.max - price) / (scale.max - scale.min)) * height;
}
```

**强制复用这一个映射**：

- 上下影线：`high` → `highY`、`low` → `lowY`。
- 蜡烛实体：`open` → `openY`、`close` → `closeY`。
- MA 线：每个 MA 价格 → Y 坐标。
- 右侧价格刻度：刻度值 → Y 坐标。
- 左侧百分比轴：先在同一价格刻度上通过 `((price - prevClose) / prevClose) * 100` 计算对应百分比，不创建第二套独立的几何比例尺。
- 极值注记：从对应影线的实际端点定位，不能靠固定偏移或独立百分比算法估算。

### 4.3 极值必须在画布内

采用独立的布局边界：

```ts
const plotTop = paddingTop;
const plotBottom = containerHeight - paddingBottom;
```

保证：

```ts
plotTop <= priceToY(bar.high, scale);
priceToY(bar.low, scale) <= plotBottom;
```

为图表底部保留足够的 X 轴标签空间，不能让最后一排价格/影线落到容器外。必要时使用 `ResizeObserver`（或项目已有容器测量机制）重新计算 `plotTop/plotBottom`。

### 4.4 影线、实体、坐标精度

- 同一根 K 线的实体与上下影线必须共享 `centerX`。
- **上涨红、下跌绿**，保留插件现有语义。
- 影线绘制从 `highY` 到 `lowY`，不会被实体高度的最小像素限制反向影响。
- 实体较矮时可以显示为最少 1 个物理像素的可见线，但不得因此改变真实 OHLC 或影线端点。
- X 轴根据交易时段映射；若存在真实数据缺口，不要将相邻柱错位挤占为完整连续数据。
- 轴线、十字线可按设备像素栅格对齐，但**不要简单地对所有 CSS 坐标无条件加 `0.5px`**；需要结合 Canvas/SVG 渲染方式与实际 DPR 检查。

### 4.5 高清屏处理

如果现有图表使用 Canvas：

```ts
const dpr = window.devicePixelRatio || 1;
canvas.width = Math.round(cssWidth * dpr);
canvas.height = Math.round(cssHeight * dpr);
canvas.style.width = `${cssWidth}px`;
canvas.style.height = `${cssHeight}px`;
ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
```

- resize 后重新设置 transform，避免累计 `scale()`。
- 所有布局与绘图位置在统一的 CSS 像素坐标系计算。
- 若现有图表使用 SVG，则保持高精度连续数值映射，重点检查 `viewBox`、容器纵横比和裁切，**不要盲目添加 Canvas 逻辑**。

## 5. 必须补齐的最高价/最低价可视化

### 5.1 真实极值标注

在蜡烛图中：

- 找到 **5 分钟 K 线源自身的 `min(low)` 和 `max(high)`**。
- 在最低影线端点附近标出 `最低 18.52`（该数字仅为截图示例；实际使用计算结果）。
- 在最高影线端点附近标出 `最高 XX.XX`。
- 标签尽量贴近对应蜡烛并由细引导线关联，但必须防止越界、重叠。
- 如果极值出现在边缘的第一根或最后一根柱，标签应自动向绘图区内部调整。
- 相同极值出现多次时，使用稳定规则（例如首次出现）选择一个主要标注，避免文字重复。

### 5.2 快照价与 K 线极值不一致时

- 图中只标真实 K 线自身极值。
- 标题/信息栏另显示 `日行情最低 18.52（K线源未覆盖）` 等说明。
- 不把 `18.52` 当成某根 K 线的最低价“补画”出来。
- 如果没有可靠的交易日/时间戳用于对账，不显示“数据不一致”的确定结论，而显示数据时点不明确或暂不可比较。

### 5.3 鼠标悬停核对

在现有 K 线上增加或完善 hover 十字线（不增加新图表）：

- 准确定位最近的一根 K 线。
- 展示时间、开、高、低、收，成交量有值时一并显示。
- 数值必须来自这根 K 线的原始规范化数据，而不是按鼠标 Y 位置反推伪 OHLC。
- 悬停价格横线可使用反算 `yToPrice()`，但仅作为光标参考价，与实际 K 线 OHLC 独立。
- 最新一根尚未收盘时，明确标识“进行中”。

## 6. 解决图表底部不可见、过度占高

结合截图，图表占据较大的页面纵向空间，底部附近有 DSH 自身的任务浮层。要求：

1. 宽屏工作区应使用**左股票树 / 右详情区域**，右侧容器高度随可用工作区伸缩，而不是写死一个会溢出的巨型画布。
2. 绘图区的上、下边界必须以**实际可见的图表容器**为准，不以整页文档高度为准。

## 10. 验收标准与回归测试

### 10.1 确定性数据测试

**用例 A：K 线数据确实包含最低价**

- 构造合法 5 分钟柱数组，其中至少一根 `low = 18.52`，另有 `high = 20.27`。
- 验证计算出的极值分别为 `18.52` 和 `20.27`。
- 验证这两根影线端点均位于 `plotTop` 与 `plotBottom` 之间。
- 验证最低标注锚定在数值 `18.52` 对应的蜡烛影线上。
- 调整图表尺寸后重新计算，仍满足以上条件。

**用例 B：行情快照最低价在 K 线中不存在**

- 快照 `dayLow=18.52`，合法 5 分钟柱最小 `low=19.40`。
- 图表真实最低影线必须是 `19.40`；不得生成 `18.52` 的假影线。
- 数据可比时在详情中出现适当的“当前 5 分钟数据未覆盖行情最低价”提示。
- 未确认交易日和数据口径可比前，不应误报为确定性数据错误。

**用例 C：价格轴一致性**

- 对任意输入价格 `p`，同一 `priceToY(p)` 被蜡烛、MA、刻度及辅助线复用。
- Y 值与价格单调反向：价格越高，Y 越小。
- 若左轴为涨跌幅，使用同一价格刻度计算百分比，不能出现左右轴同一 Y 表示不同价格。

**用例 D：异常与边界**

- 单根 K 线、所有柱同一价格、零成交量、缺失交易时段、无有效数据、分辨率变化。
- 所有公式无 NaN / Infinity，极值标签不出界。
- 数据空缺时正确提示，不生成虚构交易柱。

### 10.2 界面回归

- [ ] 工作区宽屏：左股票树、右详情，任意选中证券的高低点均可见。
- [ ] 侧边栏窄屏：无横向异常溢出，图表与价格刻度可读。
- [ ] Mac Retina 屏：影线清晰，蜡烛没有错位或模糊感。
- [ ] DSH 任务浮层存在时：图表关键数据与最低价不因固定高度而永久被挡住。
- [ ] K 线模式：切股票不改变模式；切回仍正确显示对应证券。
- [ ] 当日数据模式：没有分时图，字段缺失显示 `—`。
- [ ] 原有添加股票、分组、拖拽、右键、提醒入口功能不回归。

### 10.3 最终完成判定（必须全部满足）

1. **有源数据的最低/最高价，既能在数据中验证，也能在图形中定位。**
2. **没有源数据的极值，不会被错误绘入图形；两类行情存在差异时可解释。**
3. **蜡烛、价格刻度、涨跌幅刻度使用同一坐标系统。**
4. **即使窗口变化或 DSH 底部有宿主浮层，关键高低点也不会因为画布布局问题而不可见。**
5. **用户可手动在“当日数据 / 5分钟K线”切换，且没有新增分时图。**
6. **HTML 原型可独立打开并演示切换、最低价定位、数据源差异及调试信息，且开发版本的交互行为应与原型一致。**
6. **现有测试、TypeScript 类型检查和构建通过。**

## 16. 跟进任务（2026-11-02）：当日数据五项接入真实值
