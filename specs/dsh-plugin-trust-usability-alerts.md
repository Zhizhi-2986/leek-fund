# DSH 行情：可信、顺手、省心

## 1. Spec

### 目标与用户需求

1. 可信：自选和详情呈现行情时间、交易时段/过期状态，失败时旧值不得伪装成实时价；展开的详情及时跟随最新行情。
2. 顺手：把「关注」与「未分组」语义区分清楚，关键股票操作不再只有右键入口，界面与模型的重点关注能力一致。
3. 省心：用户主动建立目标价或当日涨跌幅条件；DSH 运行期间即使行情页未打开也能检查条件、生成今日关注并推送桌面通知；同一规则同一交易日只提醒一次。DSH 完全退出后的通知不保证。

### 范围

- `dsh-plugin/src/{quote,api,index,state,types,tools}.ts`：行情新鲜度、提醒规则/事件与后台检查、必要的模型工具和 API。
- `dsh-plugin/src/client/{api,index,StockTree,StockDetail,styles.module.css}.tsx/.ts`：状态呈现、操作入口、摘要、提醒设置和桌面通知；可新增聚焦的组件/逻辑文件。
- `dsh-plugin/tests/*.test.ts`：可观察行为、边界条件及 API 用例；`dsh-plugin/README.md`：使用与运行边界。
- 对已有未提交的 K 线与 Tab 位置改动只作最小兼容修改，不抹掉、不代为提交。

### 非目标范围

- 不承诺 DSH 退出后通知；不进行自动交易或荐股；不接入公告、财报或其他新数据源；不新增依赖；不修改 DSH Desktop 配置、不安装或发布、不自动提交/推送/合并。
- 不全面重构现有图表、分组、拖拽或宿主框架。

### 验收标准

1. 股票行可识别最近行情时间与数据是否新鲜；午休、非交易时段和失败/过期状态清楚区分；没有可靠时间的数据不能触发提醒。
2. 展开详情能更新当日 K 线；请求失败显示可重试状态，切换股票不展示旧详情。
3. 列表把未分组与关注标记说清，股票关键操作有可见入口；重点关注可由 UI 与模型工具同样操作。
4. 添加、查看、删除价格或当日涨跌幅规则时有输入校验；未经用户确认不新增提醒。
5. DSH 运行时宿主独立于行情 Tab 监测规则；仅在交易时段、行情时间有效且未过期时触发；持久化触发事件与去重状态，重启和多窗口不重复触发；今日关注最多展示三项，提供触发依据和时间。
6. 桌面通知由用户交互请求权限；拒绝或不支持时仍有页内事件且明确说明；通知只在 DSH 运行且客户端仍连接的能力范围内，不能承诺应用完全退出后送达。多窗口不能重复弹出。
7. `npm test`、`npm run typecheck`、`npm run bundle` 实测并记录基线问题；人工走通至少一次提醒和权限拒绝流程（环境允许时）。

## 2. Task Card

### 按依赖顺序执行

1. **可信数据**。输入：新浪行情 `time` 和现有详情 API；输出：统一新鲜度/交易时段判定、行内状态与定期详情刷新。先写缺失/过期/休市和请求失败测试，再改 `quote.ts`/`api.ts` 与客户端。验证 `npm test`、手动查看断网及休市展示。
2. **顺手操作**。输入：既有分组和标记 API；输出：清晰术语、可见操作菜单、`stock_mark` 支持 focus。先为 focus 工具及 UI 操作建测试/可验证检查，再最小修改 `tools.ts`、`StockTree.tsx` 和说明。验证原分组、排序行为不回退。
3. **规则与宿主监测**。输入：持久化状态及可验证新行情；输出：规则 CRUD、触发记录、单宿主检查循环。先写状态/API/阈值、时间、去重测试（RED），再实现；正常、断网、午休、重启和多窗口行为逐一验证。接口形式以 `AlertRule {id,code,kind,direction,threshold,enabled}`、`AlertEvent {id,ruleId,code,price,percent,quoteTime,triggeredAt}` 为准，异常拒绝非法规则。
4. **今日关注与桌面通知**。输入：宿主事件查询接口；输出：摘要、权限提示及通知消费。客户端在行情视图之外维持通知监听，浏览器原生 `Notification` 仅经用户操作申请权限；跨窗口去重由宿主事件领取/确认原子接口保证，权限拒绝回退页内。验证 Tab 关闭时和双窗口；无法验证原生通知时明确报告。
5. **审查**。依据本 Spec、Task Card、实际 diff 与命令输出填写 Review Report。结论只能是「可合并／需修复／需人工确认」。

### 允许修改

仅上述插件源文件、聚焦的新插件文件与测试、`dsh-plugin/README.md` 及本 Spec；优先保留已有用户工作。

### 禁止修改

其他项目模块、package.json/lock、DSH 配置、无关构建/部署文件；禁止提交、推送与发布。

### Review 检查点

- 行情数据的日期时区是否按 A 股交易所时间判定；午休/非交易时段与过期是否正确区分。
- 轮询生命周期、去重落盘、权限拒绝、多窗口和断网是否安全且不会过度请求上游。
- 新 API 的本地访问防护、参数验证、错误反馈及敏感信息暴露。
- 不覆盖已有未提交的 K 线、Tab 位置变更；未新增依赖或超出范围。
